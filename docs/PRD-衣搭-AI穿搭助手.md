# PRD: 衣搭 — AI 穿搭助手

## Overview

### Problem Statement

18-45 岁女性频繁面临「出门前纠结穿什么」的日常困扰，衣柜衣服不少却总觉得没衣服穿。现有 App 要么偏衣橱管理（Stylebook），要么偏社交分享（好搭），缺少一个轻量、快速、有 AI 辅助的搭配工具。同时，购买新衣服时缺乏决策参考，「这件该不该买」是高频痛点但尚无产品覆盖。

### Solution Summary

衣搭是一款面向 18-45 岁女性的 AI 穿搭助手。用户拍照上传衣物后，通过三层独立滑动（上衣/下装/鞋子）自由搭配，或使用 AI 根据天气、场合、风格一键推荐。同时提供「买前 AI 咨询」功能，辅助购买决策。

### Target Users

## Solution Design

### 页面结构

底部导航（4 Tab）：

| 页面 | 核心功能 |
|:----|----------|
| 搭配（首页） | 天气、场合、三层滑动、AI 入口 |
| 衣柜 | 分品类展示、上传入口、编辑管理 |
| AI 助手 | 买前咨询 + AI 搭配入口 |
| 我的 | 风格偏好、收藏、统计、设置 |

### 核心交互

**三层滑动搭配：**
```
👚 上衣层 ← 左右滑动切换 →
👖 下装层 ← 左右滑动切换 →
👟 鞋子层 ← 左右滑动切换 →
```

**三种 AI 模式：**

| 模式 | 触发 | 逻辑 |
|:----:|------|------|
| A：一键搭配 | 点「AI 搭配」 | 天气→场合→风格→配色排序 |
| B：补全搭配 | 选中单品 + AI | 固定选中项，AI 补全其余 |
| C：买前咨询 | AI 助手页进入 | 上传衣物信息，AI 分析 |

### AI 质量保障四层机制

1. **Prompt 规则**：详细穿搭规则（配色、廓形、场合要求）
2. **用户画像**：风格偏好 + 行为学习
3. **规则引擎兜底**：拦截明显错误，触发黄金保底方案
4. **持续优化**：记录用户偏好，逐步提升推荐

> 注：该机制中的「规则引擎兜底」对应真实产品的**匹配层**，「用户画像 / 持续优化」对应**反馈闭环**（见「真实产品架构演进（规划）」）。

### 为什么选择 DeepSeek（Demo 阶段）

DeepSeek 成本极低（`deepseek-v4-flash` 约 $0.14 / $0.28 每 1M token），手机号即可注册，国内直连无需翻墙，结构化 JSON 输出稳定。充少量余额即可跑数千次搭配，适合 Demo 阶段验证产品价值。

> **定位说明**：Demo 阶段 DeepSeek 承担"搭配推荐 + 解释"双重角色。进入真实产品后，DeepSeek 定位收敛为"解释 / 个性化层"，视觉理解与搭配匹配核心由其他层承担（见下一节）。

## 真实产品架构演进（规划）

> ⚠️ 本节为**真实产品上线前的规划**，与上文"当前 Demo"区分。**原型阶段均未实现**，在简历与面试中应表述为"方案 / 规划"，而非"已实现"。

### 为什么 Demo 架构不能直接上市

Demo 依赖"文本驱动"（把衣服的 name + color 传给 LLM），且为纯前端、无服务器。真实用户上传的是真实照片，AI 必须先"看懂"衣服；且规模化的成本 / 延迟 / 可靠性要求，决定了匹配核心不能依赖大模型逐次调用。

### 四层架构设计

| 层 | 职责 | 选型方向 | 成本性质 |
|----|------|----------|----------|
| ① 视觉理解层 | 拍照 → 结构化属性（品类/颜色/图案/材质/廓形） | 国内多模态 VLM（如 Qwen-VL / GLM-4V 等，以最新版为准） | 一次性识别成本（录入衣柜时），单张约 ¥0.01–0.05 |
| ② 搭配匹配层 | 基于属性的配色/场合/廓形规则判断 + 穿搭知识库；可选向量检索 | 规则引擎（纯代码）+ 知识库表；V2 引入 CLIP 类向量检索 | ≈ 0（无 API 成本，毫秒级） |
| ③ 解释/个性化层 | 为候选搭配生成理由、按用户风格偏好改写 | DeepSeek `deepseek-v4-flash`（非思考模式） | 每次约 ¥0.0005–0.001，可模板化进一步降低 |
| ④ 反馈闭环 | 记录采纳/收藏/换搭 → 反哺规则权重与个性化 | 服务端数据库 + 行为埋点 | 开发成本；自研兼容性模型（需标注）为 V2+ 项 |

### 基础设施（规划）

- 云存储（对象存储）存衣物图片；数据库存用户 / 衣柜 / 反馈记录
- Serverless 后端（或轻量云服务器）承载 API 与规则引擎
- 视觉识别一次录入、长期复用；匹配层不调用大模型

### 成本结构预期

| 项目 | 类型 | 预期成本 |
|------|------|----------|
| 视觉识别（约 30 件衣物） | 一次性 | ¥0.3 – 1.5 |
| 匹配规则引擎 | 每次 | ¥0 |
| DeepSeek 解释（每次搭配） | 每次 | ¥0.0005 – 0.001 |
| 云存储 + 数据库 | 每月 | 免费额度内 ≈ 0 |
| 服务器 / Serverless | 每月 | 免费额度起步，有量后 ¥50 – 150 |

以 1000 日活、人均 2 次/天估算，月现金成本约 ¥60–150，大头是服务器而非 AI。

### 演进节奏

- **MVP 真实版**：视觉（国内 VLM）+ 规则 / 知识库匹配 + DeepSeek 解释，先跑通"能用"
- **V2**：接入反馈数据，训练 / 调优兼容性模型或向量检索，替换 / 增强规则层；买前咨询对衣柜做检索比对
- 不上最大模型、不一步到位自研模型——钱花在验证上，不花在炫技上
